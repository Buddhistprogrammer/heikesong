# 魔搭创空间部署说明

本项目是 HTML/CSS/JavaScript 前端 + Python 后端，需要选择「编程式创空间 → Docker」。
不要选择 Static：它不能运行本项目的聊天、语音和生图后端。

## 上传与设置

1. 解压专用部署包，打开 `heartward-modelscope` 文件夹。
2. 在支持 Docker 的创空间中上传该文件夹的全部内容。空间文件列表最外层应直接看到 `Dockerfile`、`app.py`、`backend/`、`web/`、`解忧漫游_原型的世界/`，不要再嵌套一层 `heartward-modelscope/`。最后一个目录只含后端需要的 3 个剧情与规则文件，不能漏传，也不需要安装 Godot。
3. 若使用截图里的「快速创建并部署」，部署设置阶段选择 Docker（如果该入口没有 Docker 选项，改用「创建创空间 → 编程式创空间 → Docker」）。
4. 按平台要求绑定阿里云账号并完成实名认证；Docker 创空间有此要求。
5. 在创空间「设置 → 环境变量」配置运行时变量 `DASHSCOPE_API_KEY`，值为自己的百炼 Key。不要把真实 `.env` 上传到空间文件。
6. 保持服务端口为 `7860`，监听地址为 `0.0.0.0`。不要使用 Windows 的 `启动体验.bat` 或 `python launch.py` 作为云端启动命令。Dockerfile 已指定 `python -u app.py`。
7. 提交代码后在设置中点击「上线」，分别检查构建日志与运行日志。运行日志应出现 `Heartward listening on 0.0.0.0:7860`。
8. 应用页面打开后验证首页箭头、沙漠星星、聊天与手动朗读。应用地址下 `/health` 应返回 `status: ok`；服务是否真正可用还要以实际调用结果为准。

默认模型：`PET_CHAT_MODEL=qwen-plus`、`PET_IMAGE_MODEL=qwen-image-2.0`、`PET_ASR_MODEL=qwen3-asr-flash`、`PET_TTS_MODEL=qwen3-tts-flash`、`PET_TTS_VOICE=Cherry`。可以在运行时环境变量中覆盖；语音单独 Key 使用 `PET_VOICE_API_KEY`。

## 上传阶段的 FC async task Failed

如果红色提示仍出现在第 1 步「空间文件」，说明上传/文件处理任务失败；此时尚未启动 Python 服务，不能直接认定是代码、API Key、余额或端口造成的。

- 本专用包排除了开发工具、旧引擎、缓存和真实密钥，只保留运行文件；最外层部署目录使用英文名。旧工程目录仅保留 3 个后端依赖文件。
- 可先仅上传 `Dockerfile`、`app.py` 和说明文件，确认小批量文件能否处理，再上传全部其他文件夹。这只是定位上传故障，完整代码到齐后再上线。
- 小文件也失败时，可刷新后重试，或使用页面提供的「通过 Git 上传」。Git 地址和分支以自己的创空间给出的值为准，令牌不要发在聊天中。
- 仍失败时向魔搭支持提供失败任务 ID、发生时间、创空间地址，并说明在「空间文件」第 1 步失败；平台端任务日志才能进一步确定原因。
- 如果第 1 步成功、之后上线失败，查看「构建日志」和「运行日志」的具体异常；不要只看任务状态。若基础镜像拉取失败，应按该构建日志处理，不能与上传任务失败混为一谈。

## 运行限制

这是演示部署：重启后内存中的会话、任务会清空，当前生成宠物文件使用容器内本地目录，不保证持久化；本包未增加多人账号及会话隔离。麦克风需要 HTTPS 和浏览器授权。
